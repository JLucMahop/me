The landscape of operating systems research continues to evolve rapidly, driven by emerging hardware architectures, new application demands, and the persistent quest for better performance, security, and reliability. Recent publications from premier systems conferences like SOSP and OSDI reveal several transformative research directions that are reshaping how we think about OS design. This post explores the main research axes currently driving innovation in operating systems, examining the core problems, recent solutions, and the key industry players investing in these areas.

## Formal Verification and Kernel Correctness

Operating system kernels are notoriously difficult to verify due to their complexity and the severe consequences of bugs. The fundamental challenge is ensuring that kernel implementations faithfully follow their specifications while maintaining performance and practical usability. Traditional testing approaches cannot guarantee correctness across all possible execution paths, leaving systems vulnerable to subtle but critical bugs that can compromise security and reliability.

Recent work has made significant strides in practical OS verification. [Verus](https://verus-lang.github.io/verus/), which won the Distinguished Artifact Award at SOSP 2024, represents a breakthrough in making verification accessible for systems programmers. Built on Rust, Verus provides efficient proof automation that scales to large, complex systems, demonstrating that verified systems code can be both practical and performant. The project has already seen industrial adoption at Microsoft and Amazon, with two of the three best papers at OSDI 2024 built on its foundations. At SOSP 2024, researchers also presented [OZZ](https://dl.acm.org/doi/10.1145/3694715.3694759), a best paper that identifies kernel out-of-order concurrency bugs through in-vivo memory access reordering, addressing a particularly insidious class of kernel bugs that traditional verification methods struggle to catch. The [seL4 microkernel](https://sel4.systems/) project continues to set the gold standard, having achieved the first complete formal verification of a general-purpose OS kernel's functional correctness from abstract specification down to C implementation as presented in [their SOSP 2009 paper](https://dl.acm.org/doi/10.1145/1629575.1629596). These advances show that formal methods are transitioning from academic curiosities to practical tools that can significantly improve kernel reliability. Microsoft and Amazon are leading industrial efforts in this space, with Google also investing heavily in kernel verification technologies through projects focusing on memory safety and concurrency correctness.

## Memory Disaggregation and CXL Integration

Modern datacenters suffer from significant memory stranding, where memory resources remain locally bound to servers even when underutilized, while other nodes experience memory pressure. This rigid coupling between compute and memory leads to poor resource utilization and limits system flexibility. The fundamental problem is enabling efficient access to remote memory with latency and bandwidth characteristics that don't severely degrade application performance.

Compute Express Link (CXL) technology is revolutionizing how we approach memory disaggregation. At OSDI 2024, researchers from Microsoft presented [work on managing memory tiers with CXL in virtualized environments](https://www.usenix.org/conference/osdi24/presentation/zhong-yuhong), introducing hardware-managed tiering systems that provide performance close to regular DRAM with minimal degradation for most workloads. Their full-system prototype demonstrated that careful management of memory tiering can maintain application performance while dramatically improving memory utilization across the datacenter. SOSP 2023 featured [groundbreaking work on partial failure resilient memory management](https://dl.acm.org/doi/10.1145/3600006.3613159) for CXL-based distributed shared memory, addressing the critical challenge of maintaining system reliability when memory is disaggregated across multiple physical machines. At SOSP 2024, [SWARM](https://dl.acm.org/doi/10.1145/3694715.3694761) tackled the problem of replicating shared disaggregated-memory data with minimal overhead, enabling fault-tolerant distributed memory systems that can survive node failures without significant performance penalties. These papers demonstrate that CXL enables a new class of memory architectures where compute and memory resources can be independently scaled and managed. Intel, Microsoft, and Alibaba are at the forefront of CXL-based memory disaggregation, developing both hardware platforms and software stacks to enable this technology in production environments.

## eBPF and Programmable Kernel Extensions

Operating system kernels have traditionally been monolithic and difficult to extend, forcing users to choose between kernel modifications (requiring expertise and risking stability) or user-space solutions (sacrificing performance). The core challenge is enabling safe, efficient kernel customization without compromising system security or stability. Users need the ability to extend kernel functionality dynamically for specialized workloads in networking, storage, and observability without the risks associated with traditional kernel modules.

Extended Berkeley Packet Filter (eBPF) has emerged as a transformative technology for safe kernel programmability. At OSDI 2022, [XRP demonstrated](https://www.usenix.org/conference/osdi22/presentation/zhong_1) how eBPF can be used to implement in-kernel storage functions that achieve speedups close to kernel-bypass solutions while retaining OS integration benefits. By placing eBPF hooks in the NVMe driver's interrupt handler, XRP enables efficient request chaining for operations like B-tree traversals, dramatically reducing storage access latency. The [2024 ACM SIGCOMM Workshop on eBPF and Kernel Extensions](https://dl.acm.org/doi/proceedings/10.1145/3672197) showcased the technology's rapid evolution, with papers addressing verification challenges, security concerns, and new applications in networking and observability. [SafeBPF](https://dl.acm.org/doi/10.1145/3689938.3694781) presented hardware-assisted defense mechanisms to protect against malicious eBPF programs, while other work explored formal verification methods to ensure eBPF program correctness before deployment. These advances demonstrate that eBPF is moving beyond packet filtering to become a general-purpose mechanism for kernel customization, though significant challenges remain in verification, composition, and performance optimization. Meta, Google, and Netflix are heavily invested in eBPF, using it for production-scale networking, load balancing, and observability infrastructure across their massive fleets.

## Virtualization and Containerization: Bridging Isolation and Efficiency

Virtualization and containerization technologies form the backbone of modern cloud infrastructure, yet they face an ongoing tension between providing strong isolation guarantees and maintaining operational efficiency. Virtual machines offer complete isolation through hardware virtualization but come with significant overhead in terms of boot time, memory footprint, and inter-VM communication. Containers provide lightweight alternatives with minimal overhead but share the kernel with the host, creating potential security vulnerabilities when running untrusted workloads.

Recent research has focused on narrowing this gap from both directions. At OSDI 2024, researchers presented the [HongMeng production microkernel](https://www.usenix.org/conference/osdi24/presentation/chen-haibo), a commercialized general-purpose microkernel deployed on tens of millions of devices including smartphones, smart routers, and vehicles. HongMeng achieves full Linux API/ABI compatibility while maintaining microkernel security properties through differentiated isolation classes, flexible composition, and address-token-based access control. This work demonstrates that microkernels can be practical for production deployment in diverse scenarios without sacrificing performance. [LightVM](https://dl.acm.org/doi/10.1145/3132747.3132763), presented at SOSP 2017, showed that with careful redesign of the virtualization control plane, VMs can boot in 2.3ms—comparable to Linux fork/exec and orders of magnitude faster than Docker. At the 2024 ACM Symposium on Cloud Computing, [ConMonitor](https://dl.acm.org/doi/10.1145/3698038.3698520) introduced a lightweight container protection architecture using compact virtualization software to create a trusted computing base that protects container applications from untrusted OS while maintaining efficiency. The 2023 SOSP paper on [PVM](https://dl.acm.org/doi/10.1145/3600006.3613163) presented efficient shadow paging for deploying secure containers in cloud-native environments, addressing the fundamental challenge of protecting containers in multi-tenant settings. These innovations show that the traditional tradeoff between isolation and efficiency is not fixed—careful system design can achieve both. VMware, Huawei, and Red Hat are leading industrial development in this space, with VMware focusing on enterprise virtualization optimization, Huawei commercializing microkernel architectures through HongMeng, and Red Hat driving container security innovations through projects like Podman and CRI-O.

## Confidential Computing and Trusted Execution Environments

As cloud computing becomes ubiquitous, protecting data in use has emerged as a critical challenge. While encryption at rest and in transit are well-established, data must be decrypted during computation, exposing it to potential attacks from compromised hypervisors, malicious cloud operators, or co-located tenants. Trusted Execution Environments (TEEs) promise to address this by creating hardware-isolated regions where sensitive code and data can execute securely, but practical deployment faces significant challenges around performance overhead, compatibility, and the evolving threat landscape.

Recent hardware advances and systems research are making confidential computing increasingly practical. Intel's Trust Domain Extensions (TDX) and AMD's Secure Encrypted Virtualization with Secure Nested Paging (SEV-SNP) provide VM-level confidential computing, enabling "lift and shift" deployment of legacy applications with minimal modifications. [Honeycomb](https://www.usenix.org/conference/osdi23/presentation/mai), presented at OSDI 2023, extended confidential computing to GPUs by securing GPU executions via static validation within AMD SEV-SNP TEE VMs, achieving near-native performance with less than 2% overhead for large language model workloads. This work is particularly significant as GPU-accelerated workloads become central to AI applications. The [ASPLOS 2024 paper on VEIL](https://dl.acm.org/doi/10.1145/3623278.3624763) introduced a protected services framework for confidential VMs that enables secure inter-VM communication and resource sharing without exposing sensitive data to the host. A [comprehensive empirical analysis](https://dl.acm.org/doi/10.1145/3700418) comparing Intel TDX and AMD SEV-SNP revealed critical insights about their performance characteristics, memory management overhead, and I/O inefficiencies that inform practical deployment decisions. However, the recent [TEE.Fail attack](https://www.bleepingcomputer.com/news/security/teefail-attack-breaks-confidential-computing-on-intel-amd-nvidia-cpus/) demonstrated that memory-bus interposition on DDR5 systems can extract secrets from SGX, TDX, and SEV-SNP, highlighting that confidential computing security remains an active research area requiring continued hardware and software co-design. Intel, AMD, and NVIDIA are driving hardware TEE development, while Microsoft Azure, Google Cloud, and AWS are deploying confidential computing services at scale, with Microsoft and Google leading in integration and attestation services.

## Serverless Computing and Cold Start Optimization

Serverless computing promises effortless scaling and pay-per-use economics, but faces a fundamental challenge: cold start latency. When a function hasn't been invoked recently, the platform must load the function code, initialize the runtime environment, and provision resources before executing the request. For modern workloads, especially those involving large language models, this initialization can take minutes, making serverless impractical for latency-sensitive applications. The problem is compounded by the tension between keeping functions warm (wasting resources during idle periods) and accepting high cold start penalties.

Recent research has tackled this problem from multiple angles. At OSDI 2024, [ServerlessLLM](https://www.usenix.org/conference/osdi24/presentation/fu) introduced a comprehensive solution for serverless LLM inference that reduces cold start latency by 10-200× through three key innovations: fast multi-tier checkpoint loading that efficiently utilizes the entire storage hierarchy on GPU servers, efficient live migration that enables newly initiated inferences to leverage locally cached checkpoints, and startup-time-optimized scheduling that intelligently places models on servers to minimize initialization time. The system demonstrates that even massive models like Llama-70B can be served with acceptable latency in serverless environments. [Work presented at OSDI 2023](https://www.usenix.org/conference/osdi23/presentation/wei) explored using RDMA-codesigned remote fork mechanisms to eliminate provisioned concurrency requirements, enabling true on-demand function invocation with microsecond-scale startup times. At the [2024 ACM Symposium on Cloud Computing](https://dl.acm.org/doi/10.1145/3698038.3698527), researchers from multiple institutions examined whether cold starts could be "put in the deep freeze" through predictive prewarming and opportunistic pre-loading strategies that anticipate function invocations before they occur. Another [SoCC 2024 paper](https://dl.acm.org/doi/10.1145/3698038.3698509) investigated pre-warming with opportunistic pre-loading to accelerate serverless inference by intelligently caching models based on predicted usage patterns. These approaches show that addressing cold starts requires co-design across the storage system, network infrastructure, and scheduling policies. AWS Lambda, Microsoft Azure Functions, and Google Cloud Functions are intensively developing cold start mitigation techniques, with each platform offering various keep-warm mechanisms and investing in faster initialization through improved container management and checkpoint loading systems.

## Conclusion

Operating systems research continues to address fundamental challenges that directly impact how we build and deploy systems at scale. The convergence of formal verification making kernels more reliable, CXL enabling flexible memory architectures, eBPF providing safe kernel programmability, modern virtualization bridging the isolation-efficiency gap, confidential computing protecting data in use, and serverless optimizations reducing cold start penalties represents a significant evolution in systems design. These are not isolated academic exercises but active areas of industrial investment, with major cloud providers and hardware vendors contributing both to research and production deployment.

As a research scientist working in operating systems and virtualization, I find this era particularly exciting because we're seeing theoretical advances translate into practical systems deployed at massive scale. The HongMeng microkernel running on tens of millions of devices, CXL memory disaggregation enabling more flexible datacenter architectures, and confidential computing protecting sensitive workloads in public clouds all demonstrate that systems research can have real-world impact. As we look ahead, the integration of these technologies promises operating systems that are simultaneously more reliable, more flexible, more efficient, and better suited to the demands of modern cloud-native and AI-driven workloads. The research community and industry are clearly aligned on these priorities, suggesting that the next generation of operating systems will look markedly different from today's designs.
